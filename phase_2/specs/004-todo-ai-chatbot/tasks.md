**Purpose**: Implement SQLModel entities for Conversation and Message storage

### Conversation & Message Model Tasks

- [X] T301 [P] Create Conversation SQLModel entity in `backend/src/models/conversation.py`:
  - Fields: `id` (UUID primary key), `user_id` (FK to users.id, indexed), `created_at` (UTC datetime), `updated_at` (UTC datetime)
  - Relationships: `messages` (back_populates="conversation", cascade delete)

## Phase 4: Chat Endpoint & Frontend Integration

**Purpose**: Implement /api/v1/chat REST endpoint and frontend ChatKit integration
**Dependencies**: Requires Phase 1, 2, 3 completion
**Checkpoint**: Full E2E chat working - user sends message → agent processes → task created → response shown

### Backend Chat Endpoint Tasks

- [ ] T324 Create chat router in `backend/src/routers/chat.py`:
  - POST /api/v1/chat endpoint with JWT authentication required
  - Request validation: ChatRequestBody(message: str, conversation_id?: str)
  - Route handler flow:
    1. Extract user_id from JWT (request.state.user_id)
    2. If conversation_id provided: load existing conversation (verify user_id matches)
    3. If conversation_id not provided: create new conversation
    4. Load full message history: message_service.list_by_conversation(user_id, conversation_id)
    5. Create agent context: build_agent_context(message_history, user_id)
    6. Invoke agent: invoke_agent(agent, context.conversation_history, current_message, user_id)
    7. Parse agent response for tool calls
    8. Execute any MCP tool calls
    9. Save user message: message_service.create_message(conversation_id, user_id, 'user', message)
    10. Save AI response: message_service.create_message(conversation_id, user_id, 'assistant', agent_response)
    11. Reload updated messages
    12. Return: ChatResponseBody(response, conversation_id, messages)
  - Error handling:
    - 401 Unauthorized if JWT invalid/expired
    - 400 Bad Request if message empty or > 2000 chars
    - 404 Not Found if conversation_id doesn't belong to user
    - 500 Server Error with logged stack trace for OpenAI API failures
  - Reference: spec.md §FR-001, FR-011, FR-012, plan.md Step 4

## Parallelization Strategy

**Can be done in parallel**:
- T301, T302: Database models (different files)
- T303: Pydantic schemas (depends on models from T301-302, but same phase)
- T311-314: MCP tools (all tools are independent, no dependencies)
- T327-332: Frontend components (all independent)
- T332-333: Styling (independent)

**Must be sequential**:
- T304 → T305 (migration must run after creation)
- Phase 1 → Phase 2 (Phase 2 depends on Phase 1 models)
- Phase 2 → Phase 3 (Agent needs MCP tools from Phase 2)
- Phase 3 → Phase 4 (Endpoint needs agent from Phase 3)
